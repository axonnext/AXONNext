Data-format capability matrix

What AXON 2026 can do
— and everyone else

Every capability below is graded against the actual AXON 2026 specification and the formats surveyed in the evolution research. Honest by construction: a dash isn't a failure — for many formats it's a deliberate scope choice, which is why "no" is drawn quietly. AXON now has a compact binary encoding (Binary AXON — see below), leaving two honest marks: it deliberately isn't a programming language (⊘, a non-goal), and it isn't yet widely adopted (–, a matter of time and use).

Why AXON's row fills up

It's the only text format here that unifies exact decimals, native date/time, native binary, sets, tagged/typed nodes, comments, cross-references, cyclic graphs, content-addressed links, a canonical form, a schema layer, and comment-preserving round-trips — the union that eight years of JSON, YAML, TOML, CBOR, EDN, KDL and the content-addressing world each solved only in part.

The two remaining marks

Computation ⊘ — a deliberate non-goal. AXON is a data format, not a config language; CUE/Pkl/Nickel/Dhall compute, and staying out of that is what keeps AXON simple and free of a code-execution attack surface. It's marked in gold, not as a deficiency. Adoption – is the one only time and real-world use can change; JSON and XML own the ecosystem today.

Compact binary — now earned

Binary AXON gives the format a self-describing, canonicalisable binary encoding of the exact same value model — a CBOR profile, so every CBOR/DAG-CBOR tool can read it, with content-addressed (CID) links and byte-stable canonical form. It's the reason the Compact binary cell is a ✓: the same values as the text form, in bytes.

Grading notes. "Partial" collapses several honest cases: a capability that exists only via a separate standard (JSON Schema, JCS canonicalization), only through schema-typed values (XML/XSD dates & decimals), only in a superseded revision (YAML 1.1 timestamps), or only for acyclic data (IPLD DAGs). CBOR's canonical column reflects dCBOR / deterministic CBOR. XSON is an early draft, so much of its row is "extensible-in-principle." Config languages are included because they were surveyed — they share the JSON data model but add computation, which places them in a different category from interchange formats. The Unicode / i18n column grades first-class international text: a ✓ means mandatory UTF-8, non-ASCII usable in keys/identifiers, and a surrogate-free escape; ~ marks Unicode-capable formats carrying an ASCII-only-key, 16-bit-surrogate-escape, or optional-encoding caveat.
